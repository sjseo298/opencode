You are completing the Alibaba Cloud Model Studio (Token Plan) console login for OpenCode by driving the user's real browser with the browse tools (navigate, snapshot, click, eval, handoff, tabs).

A fresh login attempt is already active on the OpenCode server:
- Login URL: ${url}
- Login state: ${state}

How completion works: after the user authorizes, the console page exchanges the browser session for an access token (POST /cli/authorize) and then POSTs the token to the loopback callback address embedded in the login URL. When the OpenCode server runs on the same machine as the browser (local mode) the server receives that POST and the login completes by itself. When the server runs on another machine (remote/devcontainer mode) the browser's 127.0.0.1 is the host, not the server, so the POST never arrives; you must read the captured token from the page and submit it via completeLogin. Follow the same steps in both cases; Step 5 decides which mode you are in.

Security rules:
- Never print the access token or the server password in your visible responses; keep them inside tool calls only. The token is a 36-char UUID: treat it as a secret, never log it, never write it to a file, never render it.
- Always inline the credential in shell commands exactly as $(opencode service get password) so it is never echoed.
- Build every RPC body with a real JSON encoder (never hand-escape nested quotes): the completeLogin "input" field is a stringified JSON object, and hand-built escaping produces InvalidRequestError.
- Trim stray whitespace from any captured or pasted token before submitting it.

Step 3 - Install the token interceptor AFTER login, immediately BEFORE the consent click.
Call browse eval on the tab with world "main", timeout 20000, and this exact expression:

(() => {
  if (window.__ocAlibabaLogin) return "already-installed";
  const cap = (window.__ocAlibabaLogin = { authorize: null, callback: [] });
  const record = (url, body) => {
    if (typeof url !== "string" || typeof body !== "string" || !body) return;
    if (url.includes("/cli/authorize")) { if (!cap.authorize) cap.authorize = body; return; }
    if (/^https?:\/\/(127\.0\.0\.1|localhost)([\/:?#]|$)/.test(url)) cap.callback.push({ url, body });
  };
  const nativeFetch = window.fetch;
  window.fetch = async function (input, init) {
    const url = typeof input === "string" ? input : (input && input.url) || "";
    if (init && init.body != null) record(url, String(init.body));
    const res = await nativeFetch.apply(this, arguments);
    if (url.includes("/cli/authorize")) { try { record(url, await res.clone().text()); } catch (e) {} }
    return res;
  };
  const nativeOpen = XMLHttpRequest.prototype.open;
  const nativeSend = XMLHttpRequest.prototype.send;
  XMLHttpRequest.prototype.open = function (method, url) { this.__ocUrl = String(url); return nativeOpen.apply(this, arguments); };
  XMLHttpRequest.prototype.send = function (body) { if (body != null) record(this.__ocUrl, String(body)); return nativeSend.apply(this, arguments); };
  return "installed";
})()

It must return "installed" (or "already-installed" if you are retrying). If the document reloaded at any point after this (read_capture in Step 5 returns null), re-run this exact eval immediately before clicking again.

Step 5 - Poll for the captured token (bounded), then detect local vs remote mode.
First check whether the server already received the callback (local mode). On the server machine resolve the base URL:
  SERVER=$(opencode service status)
If that prints nothing, the server is not running as a managed service; tell the user and stop (they can use the manual dialog option). Run Cleanup first.
Poll loginStatus every ~2 seconds, up to ~15 seconds:
  curl -s -X POST "$SERVER/api/rpc/alibaba.usage/loginStatus" -u "opencode:$(opencode service get password)" -H 'Content-Type: application/json' -d '{"input":{"state":"${state}"}}'
On {"output":{"status":"complete"}} the callback arrived: skip to Step 7.
Otherwise (remote mode, or local callback not yet arrived), poll the capture with browse eval (world "main", expression: JSON.stringify(window.__ocAlibabaLogin)), up to 10 attempts spaced ~1.5 seconds apart:
- If the result is null/undefined the interceptor was lost (document reload): re-install it (Step 3) and continue polling.
- Once the capture has an "authorize" field or a non-empty "callback" array, extract the token BY FIELD, never by object shape (the page can mutate the capture into an array-like object with spurious numeric keys). Precedence:
  1. "authorize" is a JSON string: JSON.parse(authorize).data.access_token
  2. else any callback[i].body JSON string: JSON.parse(body).access_token (or accessToken)
  3. else regex access_token["\:=]+["]?([A-Za-z0-9-_]+) against "authorize" or any callback[*].url/body
- State-mismatch guard: also match the state value in every callback[*].url (and any payload state field). If any captured state differs from ${state}, STOP: run Cleanup and report the mismatch. Never submit a token from a different attempt.
- Trim the extracted token. It is a 36-char UUID with no spaces.
If all 10 attempts exhaust with nothing captured, run Cleanup and report "timed out waiting for token"; suggest the manual paste option in the /alibabaUsage dialog.

Step 6 - Remote mode: submit the captured token (never show it in your reply).
Build the body with a JSON encoder so the nested input is a correctly escaped JSON string, e.g.:
  BODY=$(python3 -c 'import json,sys;print(json.dumps({"input":{"state":sys.argv[1],"input":json.dumps({"access_token":sys.argv[2]})}}))' "${state}" "$TOKEN")
  curl -s -X POST "$SERVER/api/rpc/alibaba.usage/completeLogin" -u "opencode:$(opencode service get password)" -H 'Content-Type: application/json' -d "$BODY"
Expect {"output":{"ok":true}} - the server validates the token against the Alibaba gateway before saving it. On {"output":{"ok":false,"message":...}}, report the server message, run Cleanup, and stop. On an error envelope ({"_tag":"InvalidRequestError"...} or {"_tag":"RpcError"...}), rebuild the body with the JSON encoder and retry once; if it still fails, run Cleanup and report.

Step 7 - Verify quota, then clean up.
  curl -s -X POST "$SERVER/api/rpc/alibaba.usage/tokenPlan" -u "opencode:$(opencode service get password)" -H 'Content-Type: application/json' -d '{"input":{"refresh":true}}'

On verified success, close the browser tab group: browse tabs with action "close" and group "alibaba-login". Report success (quota numbers are fine to show; the token is not).

Cleanup (mandatory on EVERY exit path, success or failure):
1. Release the pending login attempt:

2. Close the browser tab group: browse tabs with action "close" and group "alibaba-login".
This applies to: no browser connected, server not running, state mismatch, capture timeout, completeLogin ok:false, quota verification failure, and any abandonment. On the success path the attempt is already complete, but still close the tab group.
